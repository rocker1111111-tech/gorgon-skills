# 편집국 원고 조판

`render_newsroom.py`를 실제 스킬 도구로 실행한다. 인수는 `["에이전트/편집장/산출물/원고.md", "weekly", "출력파일명"]`이다. 첫 인수는 현재 편집국 위키의 정확한 상대 경로 또는 허용된 절대 경로, 둘째는 `classic`, `weekly`, `magazine` 중 하나, 셋째는 선택 파일명이다. 긴 원고를 인수로 전달하지 않는다.

- classic: A3 세로, 명조 본문 11.3pt, 3단, 신문 제호.
- weekly: 기본 양식. A4 세로, 명조 본문 10.5pt, 2단, 지표와 해설을 위한 주간지.
- magazine: 요청 시 보조 양식. A4 세로, 명조 본문 11.2pt, 2단, 큰 제목과 여유 있는 본문.

2026-11-23 사용자 확정: 스타일을 지정하지 않으면 weekly, 매거진 요청이면 magazine을 선택한다. 짧은 원고라는 이유로 magazine으로 자동 전환하지 않는다. classic은 명시적 요청 때만 사용한다. 전문 시안처럼 특정 기사별로 수동 배치한 디자인과 이 가변 기본 조판은 구분한다. 확정된 시안의 면수(주간지4/매거진5)를 새 원고에도 강제하지 않는다. 형식이 달라도 사실과 기사 범위는 동일해야 한다. 어려운 기사는 newsroom-explanation-20261123의 독자용 해설을 원고에 포함한 뒤 조판한다.

원고 첫 줄은 `# 제목`, 이후 `## 기사 제목`, `### 소제목`, 본문, `**부제**`, 표, `[출처명](https://원문주소)`, `![캡션](실제파일경로)`를 지원한다. `---`는 이 도구에서 구분선이고 강제 면 나눔은 `<!-- pagebreak -->`이다. 기존 DOCX/HWPX 변환기의 `---`는 면 나눔이므로 공용 원고에는 불필요한 구분선을 넣지 않는다. 제목 뒤 최소한 본문이 있어야 한다.

이미지는 존재하는 파일만 사용한다. DGX1 생성은 기존 moss 도구에 요청하고 prompt_id로 회수한 PNG를 원고에 연결한다. 생성형 삽화는 실제 사진/데이터가 아님을 캡션에 표시한다. 이미지를 찾지 못하면 실패하며 빈 사진자리로 성공 처리하지 않는다.

회사 작업공간 `newsroom-assets/config.json`에 허용 입력 루트와 지속 보관된 Nanum 폰트 경로가 설정되어 있어야 한다. 다른 회사나 비밀 경로를 탐색하지 않는다. PDF에는 한글 폰트가 포함된다. 출력은 `output/*.pdf`, 내부 영수증은 `receipts/*.json`이다. 이 도구는 네트워크를 호출하지 않는다.

성공 영수증의 실제 면수·원고 해시·PDF 해시·크기를 기록한다. 생성 후 PDF 전 면을 렌더하여 여백, 겹침, 고아 제목, 표·이미지, 사실과 링크를 검수한다. 스크립트 성공은 육안 검수 완료가 아니다. Gorgon 첨부 ID·메시지 ID와 다운로드 해시를 확인한다. 요청한 DOCX/HWPX는 기존 hwpx-report에 동일 원고를 전달하되 PDF와 동일 지면이라고 주장하지 않는다.

이미 완료한 작업은 재생성하지 말고 기존 영수증을 조회한다. 수정 원고는 새 버전 이름을 쓴다. 실패한 파일은 발행하지 않고 오류 원인을 보고한다.
